Lesson 0002 · Vervaeke × Proompting · ~20 min

Import: Capture at industrial scale

The scene workshop as a case study — every mechanism in ADR 0017 is a Vervaeke concept wearing work clothes.

The win: after this lesson you can explain four import mechanisms — the weight floor, the stateless map, trait/episode/rule routing, and anchor-as-vividness — in RR terms, and predict what would break if each were removed.

What import is, on the map

Import (ADR 0017) turns a Gemini AI Studio transcript into a resumable Room with seeded Memory. In lesson 1's terms: it is the Capture instance of Relevance Realization, run in batch. Live capture asks "is this present moment worth remembering?" once per beat; import asks it a few hundred times in an afternoon, over someone else's past. Same faculty, industrial throughput — which is exactly why the failure modes of RR show up here in their purest form.

The engine is a three-stage shape (backend/Services/Import/):

StageWhatWho judgesCode
Deterministic IRParse source into typed chunks. No LLM.Nobody — mechanicalAiStudioImportParser.cs
Stateless mapOne LLM call per Scene → trait | episode | rule items + per-chunk routingLLM (intra-scene granularity)SceneMapService.cs
Fold + commitMerge items into reviewable draft; human reviews; pure writesCode (mechanical merge) + human (everything else)ImportFold.cs, ImportCommitService.cs

Note the division: what is computable (parsing, dedup arithmetic, timestamp assignment) goes to code; what requires realization (what counts as an event, where scenes begin, whether "Lena" is our Lena) goes to an LLM or the human. The frame problem from lesson 1 predicts this split — you cannot write the rule for "what matters in this scene," so the pipeline routes that judgement to judgement-capable parts and keeps everything rule-writable in plain C#.

Mechanism 1: the weight floor — combinatorial explosion, measured

Lesson 1 said RR exists because everything could matter. Import proved it with numbers: extracting the reference export's message band without a floor minted roughly one Event per message — ~180 events drowning the 96 canon ones. A memory system that remembers everything has remembered nothing; the salience landscape goes flat.

The fix reuses Capture's existing bet: the extractor emits a per-episode weight (0..1) — "how much would this stick, a day later?", the same judgement ADR 0015 attaches at live capture. Episodes below ImportSettings.WeightFloor (default 0.5) route to Room history only — no AGE Event (DraftRouting.HistoryOnly, ImportModels.cs:30). The transcript stays complete as substrate; only the memorable crystallizes into the Arena.

And because a floor is a rule pretending to do RR's job, it is deliberately not final: it's a draft default, greyed-with-reason in review, flippable per item by the human. The rule proposes; realization (the human's) disposes.

Mechanism 2: trait / episode / rule — a 4P routing table

The map call's three item types are the four kinds of knowing, sorted at the door:

ItemKind of knowingWhere it landsWhy there
episodePropositional + PerspectivalAGE Event (+ Concept links) with per-Participant RecollectionsShared anchor in the Arena; each cast member gets their own spin on the edge.
traitProcedural (engagement style, identity)Persona card / system prompt — never the memory graphHow the persona engages, not something they recall. Finalize compresses traits + synthesises the Bio.
ruleNot knowing at all — meta-contentdiscarded(reason) in the conservation ledgerAuthor instructions aren't in-world experience. Recorded, never silently dropped.

And the fourth P? Participatory knowing — Stances — is deliberately absent at import time. CONTEXT.md: "beliefs don't crystallise during an experience but in the rest after it." Import writes the propositional and perspectival layers only; orientations form later, retroactively, via Consolidation (ADR 0016) — the same rest-time pass live play uses. An importer that wrote Stances directly would be claiming to know what the experience meant at the moment of having it.

Mechanism 3: the stateless map — a defence against parasitic processing

Vervaeke's name for RR gone malignant is parasitic processing: a misframing that feeds itself, each distorted interpretation becoming the lens for the next, narrowing reciprocally until the system can't see out. Superseded ADR 0013 had built exactly that channel: scene N's extractor read scenes 1..N−1 back from AGE, so one hallucinated event in scene 2 became ground truth framing for scenes 3 through 20. The ADR 0017 verdict names it precisely: "that serial chain propagates extraction errors forward."

The cure is structural, and every piece maps:

  • Independence. f(chunks, registry?, note?) → items — no running "story so far." Each scene re-realizes relevance from source, so an error stays local instead of compounding.
  • Explicit, human-owned context. Continuity comes from chunk overlap and the registry — nouns, not narrative. The registry pins names and cast routing; it never carries interpretation forward. Prior-episode injection exists but is per-scene opt-in, "the error-propagation channel the map shape exists to avoid."
  • The opening move. Vervaeke's counter to reciprocal narrowing is re-opening the frame. Here: regeneration is side-effect-free — reframe with a note ("this scene is a dream sequence"), rerun, only the draft mutates. And the human gate at commit is a second cognitive system auditing the first's framing before it becomes real.

Architect's takeaway: statefulness in an extraction chain isn't just a resumability problem — it's a frame-contamination problem. When you next design a multi-stage LLM flow, ask what each stage's errors become for the stage after it.

Mechanism 4: anchor-as-vividness — writing onto the salience landscape

Import doesn't insert facts into a database; it places memories onto a decaying landscape. The operator sets an anchor timestamp + spacing (ImportSettings.Anchor), episodes land at anchor + chunk-ordinal · spacing, and from that moment SalienceMath.Score treats them exactly like lived memories — 7-day half-life and all. ADR 0017 measured the consequence: a 30-day-old anchor yields a 38× salience gap versus a fresh one. The anchor knob is therefore not "when did this happen" metadata — it is a vividness dial: anchor last week and the persona is haunted by the backstory; anchor last year and it's a faint shape they'd only surface if the topic walks in the door (the relevant arm of recall can still reach hazy memories; the recent arm won't).

One landscape, two producers — lived beats and imported scenes — and the self-organizing dynamics from lesson 1 (pick-strengthens, time-decays) apply uniformly from the first recall onward. That uniformity is the agent–arena claim made practical: an imported Event is an Arena entity like any other; what makes it memory is only the Recollection edges personas hold toward it.

One invariant to rule them: conservation

Every IR chunk must be accounted for — event-sourced | folded | history-only | discarded(reason) | unprocessed — in the conservation ledger. RR is lossy by design (that's the point of a weight floor), and a lossy process you can't audit is indistinguishable from a broken one. The ledger makes the forgetting inspectable: nothing is ever silently lost, things are deliberately not crystallized, with the reason on record. The correction ledger (ImportCorrectionStore.cs) extends this to the human's overrides — suggested vs. final becomes ground truth for future extraction-prompt iteration in the Bench.

Check yourself

Two questions reach back to lesson 1 — that interleaving is deliberate.

1. On the four-instance RR map from lesson 1, the import workshop is primarily which instance?

Capture, run in batch: per-episode weight, floor routing, and crystallization into Events/Recollections are all forward-facing "will this stick?" judgements.

2. Without the weight floor, the measured outcome on the reference export was:

~1 Event per message (~180 vs 96). A flat salience landscape where everything is memorable — the combinatorial explosion RR exists to beat, demonstrated empirically.

3. Import writes no Stances. Which principle is that enforcing?

Capture writes propositional + perspectival only; Consolidation (ADR 0016) forms Stances later, in rest — for imported memory exactly as for lived memory.

4. ADR 0013's serial read-back chain was replaced because, in Vervaeke's terms, it was a channel for:

A hallucination in scene 2 became ground-truth framing for scenes 3..20 — reciprocal narrowing. The stateless map keeps errors local; the registry carries nouns, not narrative.

5. An operator anchors an import 30 days back instead of yesterday. The personas will:

~38× salience gap: the recent arm won't carry them, but the relevant arm (graph-walk on cast/concepts) still can — hazy backstory, not amnesia. The floor gates writing, not later reading; decay never deletes.
